Данный проект представляет собой консольное приложение преподавательской оценки студентов в соответствии с домашним заданием №2 по дисциплине «Конструирование программного обеспечения».

## Запуск

Выполните:

```bash
python3 main.py
```

Программа позволяет добавлять, просматривать, изменять и удалять студентов и критерии, выставлять, исправлять и отменять оценки, рассчитывать итоги, импортировать JSON-ведомость и экспортировать результаты в CSV.

После каждого изменения данные автоматически сохраняются в `data/course.json`. При следующем запуске используется этот же файл. Другой путь можно указать так:

```bash
python3 main.py --data data/other_course.json
```

Все относительные пути отсчитываются от папки, в которой выполняется команда.

Демонстрация полного сценария:

```bash
python3 main.py --demo
```

Она добавляет двух студентов и два критерия, выставляет оценки, исправляет и отменяет их, показывает отказы при неверном балле и неизвестном критерии, рассчитывает итоги и экспортирует их в `demo_results.csv`. Результаты: Иван Петров - 8.40, Анна Смирнова - 7.60.

Демонстрация использует отдельное хранилище в памяти и не меняет `data/course.json`. Существующий файл экспорта не перезаписывается. Для повторной демонстрации выберите новое имя:

```bash
python3 main.py --demo --export second_results.csv
```

Режим окончательного итога, в котором нужны все оценки:

```bash
python3 main.py --complete
```

Тесты:

```bash
python3 -m unittest discover -s tests -v
```

## Пример работы через меню

1. Команда `1`: студент `S1`, имя `Иван Петров`.
2. Команда `2`: критерий `HW`, название `Домашние задания`, максимум `10`, вес `0.4`.
3. Команда `2`: критерий `EXAM`, название `Экзамен`, максимум `20`, вес `0.6`.
4. Команда `5`: студент `S1`, критерий `HW`, балл `9`, комментарий можно оставить пустым.
5. Команда `5`: студент `S1`, критерий `EXAM`, балл `16`.
6. Команда `8`: студент `S1`. Результат - `8.40/10`.
7. Команда `10`: путь к новому файлу, например `results.csv`.

Дробные числа в меню можно вводить с точкой или запятой. Команда `5` повторно для той же пары студент-критерий исправляет оценку. Команда `7` отменяет её.

## Правила и расчёт итога

- Номер и имя студента, номер и название критерия обязательны. Пробелы по краям удаляются. Номера уникальны внутри своего типа, регистр учитывается. Однофамильцы с разными номерами допустимы.
- Максимальный балл и вес критерия - конечные положительные числа. Вес задаёт относительный вклад, сумма весов не обязана равняться единице. Нулевые веса в этой версии не используются.
- Балл - конечное число от нуля до максимума критерия включительно. Дробные баллы разрешены. `NaN`, бесконечности, логические значения и строки вместо чисел отвергаются моделью.
- Оценка выставляется только существующему студенту и только по критерию из текущего рубрикатора. Для пары студент-критерий хранится одна актуальная оценка.
- Итог каждый раз рассчитывается по текущим критериям и оценкам. Отдельного сохранённого итогового балла нет.
- Изменение максимума критерия проверяет все выставленные по нему оценки. Если хотя бы одна станет недопустимой, не изменяются ни критерий, ни оценки. Допустимое изменение максимума сохраняет сами баллы и обновляет их шкалу.
- Изменение весов и добавление критериев сразу учитываются при следующем расчёте.
- Удалить студента или критерий с оценками нельзя: сначала нужно отменить связанные оценки. Это предотвращает случайную потерю оценок и висячие ссылки.

Формула текущего итога:

```text
итог = 10 * сумма(балл / максимум * вес) / сумма(весов всех критериев)
```

Шкала итога - от 0 до 10. Пропущенная оценка в текущем режиме вносит ноль, а её критерий остаётся в знаменателе. Например, за единственное выполненное ДЗ нельзя автоматически получить максимальный итог за весь курс.

Для примера выше: `10 * (9 / 10 * 0.4 + 16 / 20 * 0.6) / (0.4 + 0.6) = 8.4`.

В режиме `--complete` формула та же, но при отсутствии хотя бы одной оценки расчёт отклоняется. Выставленный ноль считается имеющейся оценкой. Без критериев итог не определяется в обоих режимах. Если критерии есть, но оценок нет, текущий итог равен нулю.

Внутри используются `float` и `math.fsum`. Перед суммированием веса делятся на максимальный вес, чтобы не переполнить сумму больших весов. До двух знаков результат форматируется только при выводе и экспорте, округлённое значение в расчётах не сохраняется.

## DDD

Язык предметной области отражён в названиях: `Student` - студент, `Criterion` - критерий, `Evaluation` - оценка, `Score` - балл с его шкалой, `Course` - курс, `ResultService` - расчёт итога. Рубрикатор представлен набором критериев внутри курса.

| Элемент DDD | Реализация | Обоснование |
| --- | --- | --- |
| Entity | `Student`, `Criterion` | Имеют устойчивые номера. Изменение имени или названия не создаёт нового участника курса или нового критерия. |
| Entity | `Evaluation` | В пределах курса определяется парой `student_id`, `criterion_id`. Исправление меняет значение оценки для этой же пары. История версий здесь не ведётся. |
| Value Object | `Score` | Не имеет собственного идентификатора, определяется баллом и максимумом. `Score(5, 10)` равен другому `Score(5, 10)`, но отличается от `Score(5, 20)`. Объект неизменяемый и сам проверяет диапазон. |
| Aggregate Root | `Course` | Владеет студентами, рубрикатором и оценками. Только его методы меняют состав курса и связи между объектами. |
| Repository | `CourseRepository` | Порт получения и сохранения целого агрегата. Домен не знает, где он хранится. |
| Domain Service | `ResultService` | Итог зависит одновременно от студента, набора оценок и рубрикатора, поэтому рассчитывается отдельным доменным сервисом. |

В текущей версии обрабатывается один курс. Он является единственной записью репозитория, поэтому отдельный номер курса не вводится. Один агрегат выбран для простого согласованного изменения критериев и оценок в небольшом консольном приложении. При расширении до многих больших курсов границы агрегатов и способ хранения потребуют пересмотра.

Сущности представлены неизменяемыми снимками. Операции курса находят их по идентификаторам и при изменении заменяют снимок с сохранением номера. Коллекции закрыты, наружу возвращаются кортежи. Нельзя изменить максимум критерия или балл через объект, полученный из публичного свойства.

Модель не является набором DTO: `Score` проверяет диапазон, `Criterion` - максимум и вес, `Course` - уникальность, наличие связей, допустимость изменения критерия и удаления объектов. Даже вызов доменных методов без консоли сохраняет эти правила. Десериализация JSON также проходит через доменные конструкторы и методы.

## Архитектура

Выбрана облегчённая Ports and Adapters (Hexagonal Architecture).

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| Domain | `domain/models.py` | Модель, агрегат, инварианты, фабрика оценки. |
| Domain | `domain/services.py` | Доменный сервис и стратегии расчёта. |
| Domain | `domain/ports.py` | Порт репозитория. |
| Application | `application/services.py` | Сценарии работы, фасад для консоли. |
| Application | `application/ports.py` | Порты импорта/экспорта и DTO строки отчёта. |
| Infrastructure | `infrastructure/storage.py` | JSON-репозиторий, репозиторий в памяти, импорт JSON, экспорт CSV, преобразование данных. |
| Входной адаптер | `main.py` | Ввод, вывод, меню, аргументы запуска, демонстрация. |
| Composition root | `container.py` | Регистрация и связывание зависимостей. |

Стрелки импортов направлены внутрь:

- `Application → Domain`.
- `Infrastructure → Application, Domain`.
- `main.py → Application`, а при запуске также `main.py → container.py`.
- `container.py → все слои`: это точка сборки приложения.
- `Domain` зависит только от стандартной библиотеки и собственных модулей.

Консоль вызывает фасад и не работает с JSON напрямую. Фасад зависит от портов, а не от файловых реализаций. Файловые адаптеры реализуют порты через структурную совместимость `Protocol`. В домене нет `input`, `print`, `open`, CSV, JSON и путей к файлам. DTO `ResultRow` нужен только для передачи отчёта экспортёру.

## Паттерны

Использовано по одному паттерну из каждой группы.

| Группа | Паттерн | Где и какую задачу решает |
| --- | --- | --- |
| Порождающие | Фабрика | `EvaluationFactory.create` получает найденных в курсе студента и критерий, создаёт проверенный `Score` с максимумом именно этого критерия и собирает `Evaluation`. Консоль не задаёт отдельный максимум оценки. Тот же путь используется при исправлении, импорте и смене шкалы критерия. |
| Структурные | Facade | `EvaluationFacade` предоставляет консоли операции добавления, выставления оценок, расчёта, импорта и экспорта. Он координирует репозиторий, доменную модель, сервис расчёта и файловые порты. UI не дублирует последовательность загрузка-изменение-сохранение. |
| Поведенческие | Strategy | `ScoreStrategy` задаёт контракт расчёта. `WeightedScore` считает текущий итог с нулями за пропуски, `CompleteScore` требует все оценки. `ResultService` получает стратегию через DI, поэтому правило полноты меняется без изменения агрегата и меню. |

Фабрика здесь простая, как в примере задания, отдельная иерархия создателей не требуется. Основная проверка диапазона находится в `Score`, а проверка членства в рубрикаторе - в `Course`. Фабрика соединяет эти части при создании оценки. Созданную вручную оценку нельзя вставить в курс через публичный метод в обход его проверок.

## DI-контейнер

Контейнер устроен так же, как в первом ДЗ: `register_instance` регистрирует готовый объект, `register_factory` - функцию сборки, `resolve` получает зависимость.

`build_container` выбирает репозиторий и стратегию, регистрирует фабрику оценок и экспортёр, затем способы создания импортёра, доменного сервиса и фасада. Репозиторий, стратегия и фабрика оценок общие для одного контейнера. Каждый вызов `resolve(EvaluationFacade)` создаёт новый фасад с этими зависимостями.

Консоль получает фасад один раз и не обращается к контейнеру внутри операций. В тестах стратегию и экспортёр можно заменить регистрацией перед получением фасада. Автоматический поиск зависимостей и области жизни для этого проекта не нужны.

## Хранение, импорт и экспорт

JSON хранит три списка: `students`, `criteria`, `evaluations`. Полный пример находится в `examples/course.json`. Формат JSON требует двойных кавычек, в исходном Python-коде используются одинарные.

Для импорта выберите пункт `11`, введите `examples/course.json` и подтвердите замену. Импорт заменяет всю ведомость, а не объединяет её с текущей. Сначала полностью создаётся и проверяется новый агрегат, затем выполняется сохранение. При ошибке старые данные сохраняются. Повторные номера и повторные оценки в импортируемой ведомости считаются ошибками.

JSON-репозиторий читает актуальное состояние при каждой операции. Сохранение сначала записывает временный файл в той же папке, затем заменяет основной. Ошибка записи до замены не портит прежний файл. Некорректный существующий JSON не считается пустой ведомостью: программа сообщает ошибку, не затирая данные. Отсутствующий файл означает новый пустой курс.

Экспорт содержит `student_id`, `name`, `total`, разделитель - точка с запятой, кодировка - UTF-8 с BOM. Экспортёр получает готовые строки, не вычисляет итог и не обращается к репозиторию. Существующие файлы не перезаписываются, нельзя экспортировать поверх JSON-хранилища. В режиме полного итога ошибка расчёта обнаруживается до создания CSV.

CSV - отчёт об итогах, обратно импортируется полная JSON-ведомость. Для переноса курса можно использовать копию `data/course.json`. Аналитика текущей версии - индивидуальные итоги и общая ведомость.
